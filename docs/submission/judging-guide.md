# Judging evidence map

[Documentation](../README.md) · [Demo](demo-guide.md) · [Release status](../azure/deployment.md)

Five equally weighted criteria should be assessed through reproducible evidence, not service logos or aspirations.

| Criterion | Inspect now | Still required for the target release |
| --- | --- | --- |
| **Technological implementation** | [Domain/source map](../architecture/overview.md), seeded simulator, deterministic evidence, [tests and evaluators](../development/testing.md) | Identified release/image, actual Linux runtime, cloud integration and staging reports |
| **Agentic design and innovation** | [Lead/analyst workflow](../architecture/agent-workflow.md), grounding, temporal scope, explicit fallbacks | Verified Agent Framework execution/handoff/failure traces and real target-model results |
| **Real-world impact** | [Fan/analyst/player use cases](../product/user-guide.md), provenance, honest unknowns, private reference access | Actual sign-in/trial isolation, licensed football validation, capacity/cost tradeoffs and adoption evidence |
| **UX and presentation** | Match/moments/story, shared replay clock, evidence inspection, locales and ordered speech behavior | Verified trial-to-sign-in flow, representative-device accessibility/sync checks, enabled-locale review and working release URL |
| **Category adherence** | Foundry/Speech adapters and [cloud target](../azure/deployment.md) with explicit status | Actual Foundry/Framework/service use, tenant-aware foundation and cloud-native staging evidence |

## Suggested review path

1. Follow the [synthetic demonstration](demo-guide.md) so the same evidence can be reproduced.
2. Inspect a moment's metrics before reading the narrative.
3. Change persona/language and verify that facts and evidence remain unchanged.
4. Seek/pause and inspect transcript/provider labels; do not mistake browser or deterministic fallback for live Azure proof.
5. Review the readiness gate and missing evidence before awarding production or accuracy claims.

## Evidence packet

The final packet should identify a commit, immutable images, UTC date, demo URL, synthetic recipe/seed, sanitized offline/live reports, actual workflow traces, enabled locale/voice review, licensed validation provenance, and staging restore/load/alert results.
